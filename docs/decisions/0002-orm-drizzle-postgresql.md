# 0002. Drizzle as ORM, with PostgreSQL

- Status: accepted
- Date: 2026-09-30

## Context

The shop needs a relational database: orders, order lines, payments, stock and invoice references depend on transactions and integrity. Stock must never be sold twice, which requires atomic updates and constraints. The schema must live in the codebase and change through versioned migrations.

## Decision

- PostgreSQL as the database engine.
- Drizzle ORM as the data access and migration tool, with the schema defined in TypeScript and SQL migrations generated by `drizzle-kit` and committed to Git.
- The database provider and hosting are not decided here. They get their own ADR. Nothing in this decision ties the project to a specific provider.

## Alternatives considered

- Prisma: suggested during the initial brainstorming. It was not evaluated in depth against current documentation. The owner chose Drizzle, which is also the tool used in the owner's previous checklist.

## Consequences

- Schema changes go only through Drizzle migrations, never through a provider dashboard.
- Types are shared between the schema and the code.
- To confirm in the technical foundation spec, before installing anything:
  - which release channel to use (some pages of the current documentation show `@rc` packages; check what is stable at that time);
  - which PostgreSQL driver to use (the documentation shows both `postgres` and `pg`);
  - how migrations are applied in each environment.
