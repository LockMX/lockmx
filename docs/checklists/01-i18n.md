# Checklist: internationalization (PT-PT and EN)

Repeats the setup done in spec 002 (`../specs/002-i18n.md`, decision in `../decisions/0008-i18n-native-next.md`): two locales in the URL path, locale negotiation from `Accept-Language`, typed dictionaries, a language switcher and a lint rule against hardcoded text. Versions are the ones used on 2026-10. Confirm each step against the bundled Next.js docs (`apps/web/node_modules/next/dist/docs/01-app/02-guides/internationalization.md`) before repeating it.

## Prerequisites

- The technical foundation (`00-foundation.md`): typecheck, Vitest, CI.
- Next.js 16 with the App Router and a `src/` directory.

## Steps

1. **Dependencies.** From the root: `pnpm add --filter web @formatjs/intl-localematcher negotiator` and `pnpm add -D --filter web @types/negotiator`. Expected: they appear in `apps/web/package.json`. `negotiator` ships no types.
2. **Locale configuration.** `src/lib/i18n/config.ts`: `locales` (`["pt", "en"]`), `defaultLocale` (`pt`), the `Locale` type, `isLocale`, `htmlLang` (`pt` to `pt-PT`, `en` to `en`) and `localeNames` (each language in its own name). Test: `config.test.ts`.
3. **Negotiation.** `src/lib/i18n/negotiate.ts`: `resolveLocale(acceptLanguage)` parses the header with `negotiator`, drops tags that are not well formed (`Intl.getCanonicalLocales`), and matches them with `match` from `@formatjs/intl-localematcher`, falling back to the default. `match` throws `RangeError` on malformed tags, hence the filter and the `try/catch`. Test: `negotiate.test.ts` (`pt-BR` gives `pt`, `fr` gives `pt`, `*`, empty and malformed headers give `pt`, quality values respected).
4. **Dictionaries.** `src/server/i18n/messages/pt.ts` defines the shape and exports the `Messages` type; `en.ts` is typed as `Messages`. `src/server/i18n/messages.ts` exports `getMessages(locale)`. Expected: removing a key from `en.ts` fails `pnpm typecheck`. Test: `messages.test.ts` (same keys in both, no empty values).
5. **Current locale.** `src/server/i18n/current-locale.ts`: `getCurrentLocale()` reads the `lang` root parameter from `next/root-params` and calls `notFound()` for an unsupported value. Only usable in Server Components.
6. **Routes.** Move the root layout to `src/app/[lang]/layout.tsx` (`<html lang={htmlLang[locale]}>`, `generateStaticParams` returning both locales, title and description from the dictionary) and the pages to `src/app/[lang]/`. Run `pnpm typecheck` once so `LayoutProps<"/[lang]">` and `next/root-params` types exist.
7. **Proxy.** `src/proxy.ts` exporting `proxy` and `config.matcher`. A path with a supported first segment passes. Otherwise it redirects (307, `Vary: Accept-Language`) to `/<resolved locale>/<path>`, replacing a first segment shaped like a language code (`/fr`). The matcher is `/((?!api|_next|.*[.].*).*)`. Test: `proxy.test.ts`, including the matcher.
8. **Switcher.** `src/lib/i18n/switch-locale-path.ts` and `src/components/language-switcher.tsx` (client component, `usePathname`, links with `lang` and `aria-current`, label passed as a prop). Tests for both. Add `src/test/setup.ts` with `afterEach(cleanup)` and `setupFiles` in `vitest.config.mts`, otherwise component tests see the DOM of earlier tests.
9. **Lint.** In `eslint.config.mjs`: `"react/jsx-no-literals": ["error", { noStrings: true, ignoreProps: true }]`. Expected: `<p>Hello</p>` in a component fails `pnpm lint`; `className="..."` does not.
10. **Docs.** Update `docs/architecture.md` and accept the ADR.

## Common errors

- Every path except `/` returns 404 on a production server: the matcher used `\\.`. Next.js turns an escaped dot in a matcher into any character, so everything with a character is skipped. Use `[.]`. Check the compiled pattern in `.next/server/functions-config-manifest.json`.
- `Cannot find name 'LayoutProps'` in CI: types are generated by `next typegen`; the `typecheck` script runs it first.
- `Found multiple elements` in component tests: no cleanup between tests (step 8).
- `RangeError` from `match`: a malformed tag reached it (step 3).
- `pnpm lint` flags `className` strings: `ignoreProps` is missing from the rule options.

## Verification

Run `pnpm build` then `pnpm start`, and check with `curl -i -H "Accept-Language: <value>" <url>`:

| Request | Expected |
|---|---|
| `/` with `en` | 307 to `/en` |
| `/` with `pt-PT` or no header | 307 to `/pt` |
| `/fr`, `/fr/a` | 307 to `/pt`, `/pt/a` |
| `/produtos` with `en-GB` | 307 to `/en/produtos` |
| `/favicon.ico` | 200, no redirect |
| `/pt` | 200, `<html lang="pt-PT">` |
| `/en` | 200, `<html lang="en">` |

Then `pnpm lint`, `pnpm typecheck`, `pnpm test` and `pnpm build` pass.
