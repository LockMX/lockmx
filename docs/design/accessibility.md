# Accessibility

## Target

WCAG 2.1 Level AA. Source: Web Content Accessibility Guidelines 2.1, W3C Recommendation, https://www.w3.org/TR/WCAG21/ (consulted 2026-10-08). Conformance requirement 5.2.1: "For Level AA conformance, the web page satisfies all the Level A and Level AA success criteria, or a Level AA conforming alternate version is provided."

Whether a legal accessibility obligation applies to the shop is a compliance question and is not answered here.

The criteria the design system is built against, quoted from the same source:

| Criterion | Level | Text |
|---|---|---|
| 1.4.1 Use of Color | A | "Color is not used as the only visual means of conveying information, indicating an action, prompting a response, or distinguishing a visual element." |
| 1.4.3 Contrast (Minimum) | AA | "The visual presentation of text and images of text has a contrast ratio of at least 4.5:1", with exceptions for large-scale text (3:1), incidental text and logotypes. |
| 1.4.11 Non-text Contrast | AA | "The visual presentation of the following have a contrast ratio of at least 3:1 against adjacent color(s)": "Visual information required to identify user interface components and states", and "Parts of graphics required to understand the content". |
| 2.1.1 Keyboard | A | "All functionality of the content is operable through a keyboard interface without requiring specific timings for individual keystrokes", with an exception for path-dependent input. |
| 2.4.7 Focus Visible | AA | "Any keyboard operable user interface has a mode of operation where the keyboard focus indicator is visible." |
| 4.1.2 Name, Role, Value | A | "For all user interface components (including but not limited to: form elements, links and components generated by scripts), the name and role can be programmatically determined; states, properties, and values that can be set by the user can be programmatically set; and notification of changes to these items is available to user agents, including assistive technologies." |

The design system uses 4.5:1 for all text. The 3:1 allowance for large text is not relied on.

## Focus

- `globals.css` gives every focusable element a 2px outline in `--focus-ring`, offset by 2px, on `:focus-visible`. A component does not remove it; it may replace it with an indicator that still measures 3:1 against the surface.
- An inverse surface declares itself with `data-surface="inverse"`. Inside it `--focus-ring` takes the value of `--focus-ring-inverse`, because the dark ring is invisible on black. Every element that paints `--surface-inverse` or `--surface-inverse-raised` sets the attribute.
- `--shadow-focus` and `--shadow-focus-danger` are additions to the indicator, never the indicator.
- A clipped shape (the slanted button) must not clip its own focus indicator.

## Colour is never the only cue

State that colour shows is also shown by shape or text: an error has an icon and a message, a checked box has a mark, a badge has a label, a discount has "was" and "now" text for assistive technology.

Open point: the imported link style (near-black text, yellow underline) relies on an underline that measures 1.76:1 on white. It was kept as imported and is listed in `README.md` for a decision.

## Motion

`globals.css` reduces every transition and animation to an instant change under `prefers-reduced-motion: reduce`. A component that conveys progress with motion alone (a spinner) also exposes the state to assistive technology (`aria-busy`, a status message), since the motion disappears.

## Per component

Each interactive component is operable with the keyboard alone, exposes its role, name and state, and shows disabled and invalid states to assistive technology. The pattern followed (WAI-ARIA Authoring Practices, https://www.w3.org/WAI/ARIA/apg/patterns/) is cited in the notes of its task in spec 003.
