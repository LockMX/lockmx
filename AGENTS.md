# LockMX: agent instructions

Rules shared by the whole monorepo, read by Claude Code and Codex. Keep this file short: the detail lives in `docs/`.

## Project

Online store for LockMX (motocross products: tyres and racks for carrying equipment inside vans). It is a real business for a client, with personal data and payments, so security and correctness matter more than speed.

- A single Next.js site in `apps/web`: marketing, shop, customer area and admin panel.
- Languages: PT-PT and EN.
- pnpm monorepo. `packages/` only receives code once there is a second real consumer.
- Documentation index and working cycle: `docs/README.md`.

## Main rule: never assume

- Every decision is based on the latest official documentation for the installed version and on the existing project code.
- Before using a Next.js API, read the documentation bundled with the package: `apps/web/node_modules/next/dist/docs/`. For other libraries, consult the current official documentation (Context7 or the official site).
- If you cannot confirm something, say so. Do not fill gaps with what seems likely.
- External values (prices, fees, legal deadlines) are only used after being verified at the official source, with the source cited.
- If documentation and code diverge, report the divergence and propose the fix. Do not invent a new convention.
- Technology decisions are recorded in `docs/decisions/` (ADR) with the sources consulted.

## How to work

- Full flow in `docs/workflow.md`. Summary: idea, decision, spec, tasks.
- Do not implement without an approved spec, except small and obvious fixes.
- Every task has tests (write the test first), and the task commit includes code and tests together.
- If a task is ambiguous, ask before implementing.
- When a module is finished, create or update its checklist in `docs/checklists/`.

## Language

- Code, code comments, identifiers, documentation and commit messages are always written in English.
- User-facing text goes through i18n (PT-PT and EN). No hardcoded visible strings.

## Commits

- One commit per task, made at the end of the task, after the relevant lint, typecheck, tests and build pass. No approval is needed to make the commit.
- Format: `<type>: <message>`, with type `feat`, `arch`, `fix`, `refactor` or `docs` (definitions in `docs/workflow.md`).
- Message short, imperative and lowercase.
- Never mention the model or agent: no `Co-Authored-By`, no trailers, no "generated by".
- No icons, emojis or graphic symbols in commits.
- Do not push, open or merge PRs, or deploy without an explicit request.

## Code

- SOLID and Clean Code, applied concretely: small single-purpose functions, explicit names, dependencies pointing inward (business logic knows nothing about the UI or providers).
- Less is more: no speculative code, no abstraction before real use, no refactoring outside the task.
- No new production dependencies without justifying the need and asking for approval.
- A single package manager: pnpm, from the root. A single lockfile.

## Security

- Secrets never go in code, logs, examples or commits. `NEXT_PUBLIC_*` variables are public: never put secrets in them.
- Validate all untrusted input on the server. Authenticate and authorize on the server, on every action: hiding a button is not access control.
- Never trust the browser for prices, stock, discounts, totals or user identity.
- Card data never passes through this project's server: use the payment provider's checkout or tokenization.
- A payment is confirmed by the provider's webhook, with a verified signature and idempotent processing.
- Authentication, payments and personal data follow only the flows documented in `docs/`. No shortcuts.

## Commands (from the root)

- `pnpm dev`, `pnpm build`, `pnpm lint`.
- Test and typecheck commands arrive with the technical foundation spec and are recorded in `docs/workflow.md`.
- Never claim a command passed if you did not run it.

## Current state

- Open (ADR before choosing): authentication (candidate: Better Auth), payment provider, database provider and hosting, cookie consent management.
- Web app specific rules: `apps/web/AGENTS.md`.
